# Pinnacle Tracker

Отслеживание движения коэффициентов Pinnacle через [The Odds API](https://the-odds-api.com).

Отслеживаемые рынки Pinnacle: **П1 / X / П2**, **двойной шанс 1X / 12 / X2** (реальный), **все линии тоталов и фор
без четвертных** (x.25 / x.75 не берём: тоталы 1.5, 2, 2.5, 3…; форы 0, ±0.5, ±1, ±1.5…), **индивидуальные тоталы**
(если Pinnacle их даёт — на футбол обычно нет). Каждая линия отслеживается отдельно; в таблице показана основная
(коэффициенты пары ближе всего), остальные — по клику на матч.

- **Открытие линии**: каждые 15 минут бесплатно проверяется список матчей лиги; как только у Pinnacle появилась линия
  нового матча, снимаются все рынки (≈ 4 запроса квоты). Для только что добавленной лиги открытием считается первый опрос.
- **Плановый опрос**: 1X2 одним запросом на лигу (1 запрос) + все линии тоталов и фор для матчей, которые начнутся
  в ближайшие 24 ч (`LINES_WINDOW_HOURS`), — запросом по матчу (2 запроса на матч).
- **Закрытие**: за час до старта — снова 1X2, реальный двойной шанс и все линии (≈ 4 запроса).
- Между открытием и закрытием двойной шанс (курсив) рассчитывается из 1X2 того же снимка: `1X = 1 / (1/П1 + 1/X)` —
  у Pinnacle он совпадает с реальным с точностью ~0.01.
- Все линии тоталов и фор есть только в «дополнительных» рынках API (`alternate_totals`, `alternate_spreads`),
  которые отдаёт лишь запрос по отдельному матчу — поэтому они снимаются не во всех опросах.

- **Матчи** — текущий коэффициент и изменение от первого зафиксированного значения; клик — история всех снимков.
- **Просадки / Повышения** — исходы, у которых коэффициент упал / вырос от открытия на заданный % (по умолчанию ≥ 3%), с фильтром по рынку.
- **Лиги** — какие лиги опрашивать (с оценкой расхода квоты).

Фиксируется только прематч: после начала матча снимки не пишутся.
«Открытие» — первый снимок трекера: для новых матчей это 15–30 минут после появления линии у Pinnacle.

## Работа на GitHub (без своего сервера)

Опрос делает GitHub Actions (`.github/workflows/poll.yml`), сайт публикуется на GitHub Pages.

- Cron стартует каждые 15 минут, `python -m app.cli run` проверяет новые матчи, опрашивает лиги, которым пора,
  и снимает линии закрытия. Если ничего не изменилось — коммита нет.
- Состояние (все снимки) хранится в `data/state.json` и коммитится ботом после каждого опроса.
  Матчи, начавшиеся больше 14 дней назад, удаляются.
- Сайт — тот же `static/index.html`: если рядом лежит `data.json`, страница работает без бэкенда.

Настройка репозитория (один раз):
1. **Settings → Secrets and variables → Actions → Secrets**: `ODDS_API_KEY`.
2. **Settings → Secrets and variables → Actions → Variables**: `TRACK_SPORTS` (через запятую, например `soccer_epl,soccer_spain_la_liga`).
   Необязательно: `POLL_BASE_HOURS`, `POLL_NEAR_HOURS`, `NEAR_KICKOFF_HOURS`, `MIN_QUOTA_REMAINING`,
   `LEAGUE_MARKETS` (по умолчанию `h2h`), `LINES_WINDOW_HOURS` (за сколько часов до матча снимать все линии в каждом опросе,
   по умолчанию 24; 0 — только при открытии и закрытии), `CLOSE_WINDOW_MIN`.
3. **Settings → Pages → Source: GitHub Actions**.
4. **Actions → Poll Pinnacle → Run workflow** (галочка «force» — опросить сразу).

### Надёжный запуск каждые 15 минут (cron-job.org)

Расписание GitHub Actions работает «по возможности»: у небольших репозиториев запуски задерживаются на часы
или пропадают. Поэтому workflow запускается снаружи — бесплатным [cron-job.org](https://cron-job.org)
(cron в самом workflow остаётся запасным; одновременные запуски идут по очереди и квоту дважды не тратят).

1. GitHub → Settings → Developer settings → Fine-grained tokens → новый токен:
   Repository access — только `odds-viewer`, Permissions — **Actions: Read and write**.
2. cron-job.org → Create cronjob:
   - URL: `https://api.github.com/repos/KuzmaJava/odds-viewer/actions/workflows/poll.yml/dispatches`
   - Schedule: Every 15 minutes
   - Advanced → Request method: **POST**
   - Headers: `Authorization: Bearer <токен>`, `Accept: application/vnd.github+json`, `Content-Type: application/json`
   - Request body: `{"ref":"master"}`
3. «Test run» → ответ `204` — запуск принят (виден в Actions как `workflow_dispatch`).

Скрипт сам решает, что делать в каждом запуске: проверка новых матчей бесплатна, лиги опрашиваются раз в 3 ч
(за 8 ч до матча — раз в час), так что частый запуск квоту не тратит. Токен истекает — продлите его в GitHub
и обновите заголовок в cron-job.org.

Ограничения: запуски по cron GitHub могут опаздывать или пропадать (см. выше); на бесплатном плане Pages работает только у публичного репозитория.
В публичном репозитории GitHub может отключить расписание после 60 дней без активности — придёт письмо, включается одной кнопкой.

## Локальный запуск

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env   # вписать ODDS_API_KEY
.venv/bin/uvicorn app.main:app --port 8077
```

Открыть http://localhost:8077. Опрос идёт, пока запущен сервер; после перезапуска он продолжает по расписанию
(время последнего опроса хранится в БД `data/odds.sqlite`).

## Расписание и квота

Каждая лига опрашивается по своему расписанию:
- обычно раз в 3 часа (`POLL_BASE_HOURS`);
- если матч лиги начнётся в ближайшие 8 часов (`NEAR_KICKOFF_HOURS`) — раз в час (`POLL_NEAR_HOURS`), до начала матча.

Стоимость — 1 запрос квоты за каждый вернувшийся рынок. Опрос лиги (1X2) ≈ 300–400 запросов/мес на лигу;
на каждый матч ≈ 30 (открытие 4 + все линии в последние 24 ч ≈ 11 опросов × 2 + закрытие 4).
Для лиги с ~40 матчами в месяц это ≈ 1500/мес — **нужен платный план** (20K за ~$30/мес). На бесплатном плане поставьте
`LINES_WINDOW_HOURS=0`. Список матчей и пустые ответы квоту не тратят. При остатке меньше `MIN_QUOTA_REMAINING`
платные запросы останавливаются.

## Структура

- `app/poller.py` — фоновый опрос по расписанию
- `app/store.py` — SQLite (матчи, снимки, настройки)
- `app/movement.py` — изменение от открытия, просадки и повышения
- `app/markets.py` — разбор рынков API, расчёт двойного шанса
- `app/odds_client.py` — HTTP-клиент The Odds API
- `app/main.py` — FastAPI
- `static/index.html` — интерфейс
