# Pinnacle Tracker

Отслеживание движения коэффициентов Pinnacle через [The Odds API](https://the-odds-api.com).

Отслеживаемые рынки Pinnacle: **П1 / X / П2**, **двойной шанс 1X / 12 / X2** (реальный), **все линии тоталов и фор
без четвертных** (x.25 / x.75 не берём: тоталы 1.5, 2, 2.5, 3…; форы 0, ±0.5, ±1, ±1.5…), **индивидуальные тоталы**
(если Pinnacle их даёт — на футбол обычно нет). Каждая линия отслеживается отдельно; в таблице показана основная
(коэффициенты пары ближе всего), остальные — по клику на матч.

- **Все исходы снимаются в один момент** — одним запросом по матчу (1X2 + все линии тоталов и фор, ≈ 3 запроса квоты):
  - **открытие**: каждые 15 минут бесплатно проверяется список матчей; как только у Pinnacle появилась линия нового
    матча — снимок (плюс реальный двойной шанс);
  - **раз в 12 ч** (`LINES_FAR_HOURS`), пока до старта больше 13 ч (`LINES_NEAR_WINDOW_HOURS`);
  - **за 13 ч и дальше раз в 3 ч** (`LINES_NEAR_HOURS`): 13, 10, 7, 4 ч до старта;
  - **закрытие** примерно за час до старта (`CLOSE_WINDOW_MIN`), плюс реальный двойной шанс.
- Запрос по всей лиге делается только при первом подключении лиги: он снимает все матчи, которые уже висят.
- Между открытием и закрытием двойной шанс (курсив) рассчитывается из 1X2 того же снимка: `1X = 1 / (1/П1 + 1/X)` —
  у Pinnacle он совпадает с реальным с точностью ~0.01.
- Все линии тоталов и фор есть только в «дополнительных» рынках API (`alternate_totals`, `alternate_spreads`),
  которые отдаёт лишь запрос по отдельному матчу — поэтому они снимаются не во всех опросах.

- **Матчи** — текущий коэффициент и изменение от первого зафиксированного значения; клик — история всех снимков.
- **Просадки / Повышения** — исходы, у которых коэффициент упал / вырос от открытия на заданный % (по умолчанию ≥ 3%), с фильтром по рынку.
- **Лиги** — какие лиги опрашивать (с оценкой расхода квоты).

Фиксируется только прематч: после начала матча снимки не пишутся.
«Открытие» — первый снимок трекера: для новых матчей это 15–30 минут после появления линии у Pinnacle.

## Работа на GitHub (без своего сервера)

Опрос делает GitHub Actions (`.github/workflows/poll.yml`), сайт публикуется на GitHub Pages.

- Cron стартует каждые 15 минут, `python -m app.cli run` проверяет новые матчи, опрашивает лиги, которым пора,
  и снимает линии закрытия. Если ничего не изменилось — коммита нет.
- Состояние (все снимки) хранится в `data/state.json` и коммитится ботом после каждого опроса.
  Матчи, начавшиеся больше 14 дней назад, удаляются.
- Сайт — тот же `static/index.html`: если рядом лежит `data.json`, страница работает без бэкенда.

Настройка репозитория (один раз):
1. **Settings → Secrets and variables → Actions → Secrets**: `ODDS_API_KEY`.
2. **Settings → Secrets and variables → Actions → Variables**: `TRACK_SPORTS` (через запятую, например `soccer_epl,soccer_spain_la_liga`).
   Необязательно: `MIN_QUOTA_REMAINING`,
   `LEAGUE_MARKETS` (по умолчанию `h2h`), `LINES_FAR_HOURS` (12), `LINES_NEAR_HOURS` (3), `LINES_NEAR_WINDOW_HOURS` (13) —
   расписание снимков всех линий, `CLOSE_WINDOW_MIN`.
3. **Settings → Pages → Source: GitHub Actions**.
4. **Actions → Poll Pinnacle → Run workflow** (галочка «force» — опросить сразу).

### Надёжный запуск каждые 15 минут (cron-job.org)

Расписание GitHub Actions работает «по возможности»: у небольших репозиториев запуски задерживаются на часы
или пропадают. Поэтому workflow запускается снаружи — бесплатным [cron-job.org](https://cron-job.org)
(cron в самом workflow остаётся запасным; одновременные запуски идут по очереди и квоту дважды не тратят).

1. GitHub → Settings → Developer settings → Fine-grained tokens → новый токен:
   Repository access — только `odds-viewer`, Permissions — **Actions: Read and write**.
2. cron-job.org → Create cronjob:
   - URL: `https://api.github.com/repos/KuzmaJava/odds-viewer/actions/workflows/poll.yml/dispatches`
   - Schedule: Every 15 minutes
   - Advanced → Request method: **POST**
   - Headers: `Authorization: Bearer <токен>`, `Accept: application/vnd.github+json`, `Content-Type: application/json`
   - Request body: `{"ref":"master"}`
3. «Test run» → ответ `204` — запуск принят (виден в Actions как `workflow_dispatch`).

Скрипт сам решает, что делать в каждом запуске: проверка новых матчей бесплатна, лиги опрашиваются раз в 3 ч
(за 8 ч до матча — раз в час), так что частый запуск квоту не тратит. Токен истекает — продлите его в GitHub
и обновите заголовок в cron-job.org.

Ограничения: запуски по cron GitHub могут опаздывать или пропадать (см. выше); на бесплатном плане Pages работает только у публичного репозитория.
В публичном репозитории GitHub может отключить расписание после 60 дней без активности — придёт письмо, включается одной кнопкой.

## Локальный запуск

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env   # вписать ODDS_API_KEY
.venv/bin/uvicorn app.main:app --port 8077
```

Открыть http://localhost:8077. Опрос идёт, пока запущен сервер; после перезапуска он продолжает по расписанию
(время последнего опроса хранится в БД `data/odds.sqlite`).

## Расписание и квота

**Режим лиги (`LEAGUE_MODE=1`, по умолчанию в workflow).** Снимок делается одним запросом на всю лигу:
1X2 и основная линия тотала (`LEAGUE_SNAPSHOT_MARKETS=h2h,totals`, 2 запроса квоты на лигу). Основную линию выбирает
Pinnacle — она может быть четвертной (2.25), такие храним; если линия сдвинулась, на сайте видно «2.25 → 2.5».
Двойной шанс — расчёт из 1X2. Лига снимается, когда хотя бы одному её матчу пора по расписанию (раз в 8 ч,
за 13 ч — раз в 3 ч, закрытие) или появились новые матчи — так одна лига укладывается примерно в 300 запросов/мес.
`LEAGUE_MODE=0` — полный режим: запрос по каждому матчу со всеми нечетвертными линиями тоталов и фор.

У каждого матча своё расписание (см. выше): открытие, раз в 12 ч, за 13 ч до старта — раз в 3 ч, закрытие за час.
`POLL_BASE_HOURS`, `POLL_NEAR_HOURS`, `NEAR_KICKOFF_HOURS` больше не используются.

Стоимость — 1 запрос квоты за каждый вернувшийся рынок, снимок матча ≈ 3. На матч, который висит в линии ~5 дней,
≈ 45 (открытие 5 + 8 снимков раз в 12 ч + 4 снимка за 13 ч + закрытие 5). Для лиги с ~40 матчами в месяц это ≈ 1800/мес — **нужен платный план** (20K за ~$30/мес). На бесплатном плане поставьте
`LINES_FAR_HOURS=1000` и `LINES_NEAR_HOURS=1000` (все линии только на открытии, за 13 ч и на закрытии). Список матчей и пустые ответы квоту не тратят. При остатке меньше `MIN_QUOTA_REMAINING`
платные запросы останавливаются.

## Трекер (backend/, Java 21)

Опрос API и сборку `data.json` в GitHub Actions делает консольное приложение на Java 21 (Gradle, Jackson,
`java.net.http`, без Spring). Формат `data/state.json` и `data.json` тот же, что у Python-версии (`app/`),
которая осталась для локального сервера FastAPI.

```bash
cd backend
./gradlew test installDist
build/install/odds-tracker/bin/odds-tracker run   --state ../data/state.json --out ../_site --site ../frontend/dist
build/install/odds-tracker/bin/odds-tracker build --state ../data/state.json --out ../_site --site ../frontend/dist
```

Настройки — те же переменные окружения (`ODDS_API_KEY`, `LEAGUE_MODE`, `LINES_FAR_HOURS`, …).

### Настройки по лигам (`LEAGUE_SETTINGS`)

Переменная репозитория (Settings → Secrets and variables → Actions → Variables), по строке или через «;» на лигу:

```
default: full, points 13h
soccer_uefa_nations_league: league
soccer_uefa_champs_league: league, far 24h
```

- `hybrid` — П1/X/П2 часто одним запросом на лигу (1 запрос на всю лигу: раз в `far` ч, за 13 ч — раз в 3 ч) +
  все нечетвертные тоталы и форы запросом по матчу в точках `points` (2 запроса; открытие и закрытие — 3, с 1X2).
  `hybrid, points 24h 13h 4h, far 12h` — клубная лига ≈ 430–450/мес; для лиг с ~40 матчами в месяц — `far 24h` (≈ 490).
- `full` — полный режим: снимок запросом по матчу, П1/X/П2 + **все нечетвертные тоталы и форы** (≈ 3 запроса);
  `points 13h` — снимки на открытии, за 13 ч и на закрытии (≈ 9 запросов на матч: клубная лига ≈ 290–360/мес);
  можно несколько точек: `points 13h 4h`. Без `points` — по интервалам (`LINES_FAR_HOURS`, за 13 ч — раз в 3 ч).
- `league` — режим лиги: один запрос на всю лигу, 1X2 + основной тотал (≈ 2 запроса); `far 24h` — фоновые снимки раз в сутки.
- `default` — для всех лиг без своей строки.

Если квоты ключа лиги едва хватает на закрытия её предстоящих матчей, промежуточные точки пропускаются — закрытия
важнее. Без переменной действует значение по умолчанию из workflow: все лиги, включая Лигу наций и новые, —
`hybrid, points 24h 13h 4h` (все нечетвертные тоталы и форы); `far 12h`, у АПЛ, Ла Лиги, Серии А и еврокубков — `far 24h`.

### Алерты в Telegram

После каждого прогона трекер шлёт в Telegram исходы, которые сдвинулись от открытия на `ALERT_MIN_PCT` % и больше
(🔻 просадка, 🔺 рост): 1X2 и основные линии тоталов и фор. Один и тот же исход приходит снова, только когда
сдвинется ещё на столько же или развернётся. При первом включении приходит одно сообщение «бот подключён» —
уже случившиеся сдвиги не рассылаются. Алерты приходят по расписанию снимков, не в реальном времени.

1. Telegram → @BotFather → `/newbot` → токен.
2. Написать боту `/start` (или добавить бота администратором в канал).
3. Secrets: `TELEGRAM_BOT_TOKEN` — токен; `TELEGRAM_CHAT_ID` — номер чата или `@имя_канала`, можно несколько
   через запятую (например, личный чат и канал: `123456789,@my_channel`).
   Номер чата: задайте сначала только токен и напишите боту `/start` — в ближайший прогон (до 15 мин) бот сам
   пришлёт вам номер чата. Он же — в логе прогона (шаг Poll): «Чаты бота: […]».
4. Variables (необязательно): `ALERT_MIN_PCT` (5), `ALERT_MARKETS` (`1x2,total,spread`, ещё `dc`), `ALERT_SPORTS`
   (ключи лиг через запятую; пусто — все).

Ошибки отправки (неверный токен, бот не в чате) видны на сайте в «Ошибке последнего опроса»; неотправленные алерты
придут в следующем прогоне.

### Отдельный ключ API на лигу

Секрет `ODDS_API_KEYS` (Settings → Secrets and variables → Actions → Secrets) — по строке на лигу:

```
soccer_epl=КЛЮЧ_1
soccer_spain_la_liga=КЛЮЧ_2
```

Запросы по лиге идут её ключом; лиги без своего ключа — общим `ODDS_API_KEY` (он же используется для бесплатного
списка лиг). Квота считается по каждому ключу: если ключ лиги почти исчерпан (`MIN_QUOTA_REMAINING`), останавливается
только эта лига. Остаток по каждой лиге виден в шапке сайта. Ключ лиги можно узнать в каталоге: вкладка «Лиги»
показывает названия, ключи — в `data.json` (`sports[].key`), например `soccer_epl`, `soccer_italy_serie_a`.

## Сайт (frontend/, React + TypeScript)

Интерфейс — `frontend/` (Vite + React + TypeScript), собирается в статику и публикуется вместе с `data.json`.
Старая страница `static/index.html` остаётся запасной: она используется, только если `frontend/dist` не собран.

```bash
cd frontend
npm install
npm run dev     # http://localhost:5173 — /api проксируется на локальный uvicorn (порт 8077)
npm test        # vitest
npm run build   # frontend/dist — его копирует `python -m app.cli build`
```

Для разработки со статическими данными положите `data.json` (например, из `_site/`) в `frontend/public/`.

## Структура

- `app/poller.py` — фоновый опрос по расписанию
- `app/store.py` — SQLite (матчи, снимки, настройки)
- `app/movement.py` — изменение от открытия, просадки и повышения
- `app/markets.py` — разбор рынков API, расчёт двойного шанса
- `app/odds_client.py` — HTTP-клиент The Odds API
- `app/main.py` — FastAPI
- `static/index.html` — интерфейс
